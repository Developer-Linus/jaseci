- **Fix: native `sorted()`/`.sort()` key comparisons now use the canonical comparison path**: The native list-sort comparator used a private `icmp`/`strcmp` chain that mishandled most key types: `str` keys crashed LLVM verification (`E5020`), `bool` keys sorted in reverse (`True` before `False`), and tuple/list keys compared raw memory instead of their contents. `emit_sort` now delegates to the shared comparison emitter (`NaIRGenPass._emit_comparison`), so `str` keys compare length-aware and NUL-safe, `bool` keys order `False < True`, tuple and list keys compare element-wise, and bytes/set keys order correctly. Orderability is now decided from the key's semantic return type, so sorting with an object-returning key (e.g. a `Node`) reports `E5092` at compile time instead of sorting object pointers as strings, and unsigned integer keys (`u8`-`u64`) order correctly for named key functions, not just lambdas. `bool`-vs-`bool` ordering operators (`<`, `>`, `<=`, `>=`) get the same `False < True` correction. - **Fix: type-checked lambda tails unlock semantic aggregate sort keys**: The type checker typed the body of expression-bodied lambdas but skipped block-bodied ones entirely, so a `key=lambda (w: str) -> (str, int) { (w[0:1], len(w)); }` tail carried no type: the native backend could not see `tuple[str, int]`, aggregate keys containing `str` elements fell through to erased-LLVM heuristics, and unsigned aggregate keys could not resolve per-element signedness. Block-bodied lambdas with a declared return type now type and assignability-check their tail expression exactly like `return` statements do (a mismatching tail reports `E1002`). With the semantic type available, `_emit_comparison` resolves each aggregate element's signedness from the key's type args (recursively through nested aggregates), so `(u64, int)` and `list[u64]` keys order unsigned above and below 2^63, and `(str, int)` keys lower natively and compare through the string comparator.
- **Fix: bare `i8*` key values no longer count as "supported strings"**: A key whose semantic return type is unresolvable and whose LLVM type is bare `i8*` (the same type as string data and object references) used to pass the sort gate and feed its values to `strcmp`. The gradual lane now refuses it (`E5092`, the function demotes to its Python implementation); a `-> any` key returning an object therefore can never pointer-sort, and semantic `str`/`bytes` keys keep their native ordering.
